# /example - Skill Template

This file shows the pattern for writing AgentTeam skills.

There are two kinds of skills in this framework:

1. **Setup/maintenance skills** (like /adapt) - run interactively by a human in a Claude Code session using `/skillname`. Never invoked by the loop or by agents.
2. **Domain convention skills** (generated by /adapt, e.g. a digest template or scoring rubric) - applied BY AGENTS during loop cycles to keep formats, rubrics, and protocols from drifting. PROMPT.md references them by name.

State clearly at the top of each skill which kind it is.

---

## Skill File Structure

Every `SKILL.md` starts with a brief description of when to use the skill, then contains instructions Claude follows when the skill is invoked.

```
# /skillname - Short Title

Brief description of what this skill does and when to use it.

---

## When to Run

(conditions that trigger this skill)

## What This Skill Does

(step-by-step instructions Claude follows)

## Output

(what the skill produces and where it goes)
```

---

## Key Patterns

- **Declare the audience**: Setup skills are human-run in interactive sessions; domain convention skills are applied by agents mid-cycle. Write each skill for its audience and say which it is.
- **Self-contained**: Each skill file should fully specify what to do. Don't rely on other skills being loaded.
- **Generative**: Most skills produce files - new configs, customized agents, scaffolded projects, or reports.
- **Instructional**: Write skills as instructions to Claude, not documentation for humans. Claude reads the SKILL.md and follows it.

---

## Adding a New Skill

1. Create `.claude/skills/<skillname>/SKILL.md`
2. Write instructions Claude should follow when `/skillname` is invoked
3. Test by running `/skillname` in an interactive Claude Code session

Skills do not require registration - any file at `.claude/skills/<name>/SKILL.md` is automatically available as `/<name>`.

**Two skill homes:** `.claude/skills/` (this directory) holds human-run skills, available only in interactive sessions. Loop-only skills - applied by agents mid-cycle - instead live in `src/resources/loop-plugin/skills/<name>/SKILL.md`, are invisible to interactive sessions, and are addressed namespaced as `loop-plugin:<name>`. See that directory's `example-loop-skill` for the pattern.
