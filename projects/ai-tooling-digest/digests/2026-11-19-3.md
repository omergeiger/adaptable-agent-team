# AI Tooling Digest - 2026-11-19

**Theme:** Open agent interoperability and the observability layer: protocols, telemetry conventions and vendor agent frameworks

## 1. Visual Studio Code 1.147 centers the editor on agent workflows

Agent work in VS Code now gets scheduling and recovery primitives: experimental Send Later, draft save/resume, assisted permissions, and experimental model routers configured in YAML. It also adds a Browser Use preview and a vscode.allowedHarnesses setting for Claude and Codex harnesses, which lets teams that use more than one coding agent control which harnesses are allowed.

**Source:** [Visual Studio Code - Updates, version 1.147](https://code.visualstudio.com/updates/v1_147)

## 2. Mastra core 1.84.0 adds storage v2 and crash recovery for durable agents

An experimental storageVersion 2 stores a run header plus per-step rows (the release notes cite one example shrinking from 98 MB to 11 MB), and a leader-elected recovery loop resumes crashed workflow runs. Teams running long-lived Mastra agents get cheaper persistence and fewer stranded runs without writing their own recovery code.

**Source:** [GitHub - mastra-ai/mastra release @mastra/core 1.84.0](https://github.com/mastra-ai/mastra/releases/tag/%40mastra%2Fcore%401.84.0)

## 3. Agent Client Protocol v1.19.0 adds session cursors and fork-by-cursor

The release adds unstable session cursors and a cursorId on session/fork, plus method-aware payload dispatch; the unstable-v2 track adds an idempotencyKey on session/prompt and a rule that agents must cancel abandoned requests. Client and agent implementers get a way to branch sessions from a precise point and to make retries safe, which matters for editors that connect to multiple coding agents.

**Source:** [GitHub - agentclientprotocol/agent-client-protocol v1.19.0](https://github.com/agentclientprotocol/agent-client-protocol/releases/tag/v1.19.0)

## 4. crewAI 1.15.42 changes the Knowledge default to local Qdrant

Knowledge now defaults to a local Qdrant store and ChromaDB becomes an optional extra, while standalone agents can choose tools and add more later. Existing crewAI projects that relied on the implicit ChromaDB default should check their dependencies on upgrade, and new projects get a lighter default install.

**Source:** [GitHub - crewAIInc/crewAI release 1.15.42](https://github.com/crewAIInc/crewAI/releases/tag/1.15.42)

## 5. OpenTelemetry GenAI conventions clarify tool definitions and share span attributes

Two merged pull requests clarify the scope of gen_ai.tool.definitions (#721) and let the inference span and the operation-details event share attributes (#724). Instrumentation authors and observability vendors get less ambiguity about what to emit for tool-using agents, though these are merged changes and not yet a tagged release.

**Source:** [GitHub - open-telemetry/semantic-conventions-genai pull request #724](https://github.com/open-telemetry/semantic-conventions-genai/pull/724)

**Also:** [Pull request #721](https://github.com/open-telemetry/semantic-conventions-genai/pull/721)
